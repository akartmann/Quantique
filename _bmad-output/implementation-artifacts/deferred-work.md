## Deferred from: code review of 1-1b-internationalization-foundation-english-french (2026-08-06)

- **Save-compat allowlist leaves 1.0.0/1.1.0 records unreachable, and nothing guards the next bump.** `src/schemas/CaseRecordSchema.ts:143-145`. The `definition.version === '1.2.0' && ['1.0.0','1.1.0']` clause can never fire — the shipped definition is 1.6.0 — so it reads as protection it no longer provides. Pre-existing: at baseline `128f1bf` the definition was already 1.4.0, so that clause was dead then too, and this story's `1.6.0 && ['1.2.0'..'1.5.0']` addition strictly widened compatibility. Carry-forward risk: the allowlist is only sound because the canonical English `feedback` / `revisionPath` strings are byte-identical across those versions — `validateCaseRecordForDefinition` recomputes and `JSON.stringify`-compares them. Nothing enforces that for the next bump; the author who reworks an English feedback sentence and extends the array ships a silent load failure. Open Question 5 already asks whether to replace the ad-hoc allowlist with a declared compatibility range — do that before Epic 3 adds case versions.
- **`LOCALES` is presented as the single source of truth but controls nothing that matters.** `src/core/i18n/Locale.ts:5`, `src/schemas/CaseDefinitionSchema.ts:30,85,92`. Adding a third locale makes `LOCALES.length === 3` while `renditions` stays a fixed 2-tuple whose `Set` size can never exceed 2, so every case fails to parse with "A readable source must provide exactly one rendition per shipped locale" and the app boots into "content unavailable" with no clue the tuple arity is the cause. `LocalizedTextSchema` / `LocalizedTextListSchema` also hardcode `en`/`fr` under `.strict()` and would reject the new key outright. Deferred because EN+FR is hard-scoped (NFR19, ADR-010, GDD Out-of-Scope) — but if a third locale is ever considered, the real arity lives in a tuple literal, two hardcoded object schemas, and the `LocalizedText` type, not in `LOCALES`.
- **`locale` is threaded as an optional parameter with a silent `DEFAULT_LOCALE` default.** `src/core/store/AppState.ts:147,165` (`createInitialAppState`, `createAppStateFromCaseRecord`), `src/adapters/phaser/renderers/LectureBookRenderer.ts:72` (`getLocale: () => Locale = () => 'en'`). Each default converts "a call site forgot the locale" from a `tsc` error into a French player silently seeing English, in a design whose whole premise is that the locale is never captured or omitted. Four call sites must remember it today. The defaults exist to avoid touching test fixtures, and `tests/unit/LocaleStore.test.ts` now encodes the escape hatch as intended behaviour. Make the parameters required when the fixtures are next touched.
- **The book control width exists as three unlinked magic numbers.** `src/adapters/phaser/renderers/LectureBookRenderer.ts:272` draws the button at a literal `150`, `:281` shrinks against `CONTROL_WIDTH - 16`, and `tests/e2e/french-typography.spec.ts:117` asserts against a literal `134`. Nothing ties them together, so changing the button width silently desynchronises the shrink bound and leaves the e2e test passing against a stale number. Same function: the shrink loop's first iteration is a no-op (it measures at 15px then calls `setFontSize(15)`), burning one measure/reflow per control on every spread redraw.
